## Observed failure and confirmed investigation

The owner freshly exported the QIF from Quicken Classic and reported:

```text
QIF source contains unsupported control character U+0001 at line 1043, column 2. Verify the text encoding or export plain-text QIF from Quicken Classic. The source has not been changed.
```

The remote investigation has **not inspected the actual export**. The section,
field tag, complete affected record, and number of affected records are unknown.
No verified QIF meaning for U+0001 was found in the inspected Quicken format
documentation or importer paths. Do not assume it represents a newline, padding,
or a formatting marker.

The exact rejection was reproduced with fictional text under both UTF-8 and
Windows-1252. Both decoders preserve byte 0x01 as U+0001; changing between these
encodings does not remove this particular control.

### Fictional reproduction

Run from the repository root with Node 22 or 24. This reads no user files:

```javascript
const { parseQif } = require('./core/qif.js');
const source = '\r\n'.repeat(1039) +
  '!Type:Bank\r\nD11/15/2026\r\nT-42.75\r\n' +
  'P\u0001Fictional Payee\r\n^\r\n';
const bytes = new TextEncoder().encode(source);
for (const encoding of ['utf-8', 'windows-1252']) {
  try {
    parseQif(new TextDecoder(encoding, { fatal: true }).decode(bytes));
    throw new Error('Expected the alpha2 baseline to reject this fixture.');
  } catch (error) {
    if (!/U\+0001 at line 1043, column 2/.test(error.message)) throw error;
    console.log(encoding + ': reproduced U+0001 at line 1043, column 2');
  }
}
```

This example uses `P`; it establishes the failure path and location, not the
field type in the owner's file.
