# CHIMI handoff: QIF account-type marker

Tracking issue: [#2](https://github.com/scoobydont-666/Sovereign-Finance-Porter/issues/2).
Candidate: **0.1.0-alpha.3**, correcting the alpha2 source reader.

## Confirmed structural diagnosis — 2026-11-24

The owner supplied the failing export for private, temporary inspection. The
reported U+0001 at line 1043, column 2 is the entire value of a `T` field in an
`!Account` record inside an `!Option:AutoSwitch` account catalogue. It is not a
transaction amount. A later `!Clear:AutoSwitch` / `!Account` declaration selects
a different, valid account before a banking transaction section.

The source is ASCII text with CRLF line endings. Changing between UTF-8 and
Windows-1252 does not change this marker. Its account-type meaning is unknown;
there is no evidence for replacing it with a named type or a newline.

The original private file reproduced the alpha2 failure. An isolated in-memory
probe treating only this type as unspecified removed the blocker, identifying
the account metadata gate as the cause. The implementation retains the original
marker rather than editing the source.

## Implemented behavior

- `core/model.js` accepts only an exact physical `T\u0001` line in genuine
  `!Account` context. Every other control remains checked, including those after
  an accepted marker. CR/LF/CRLF positions and Unicode columns stay private.
- `core/qif.js` retains the account, treats that type as unspecified, and emits
  `ACCOUNT_TYPE_UNSPECIFIED`. Existing explicit account declarations/transaction
  sections may supply a type; the marker itself never implies Bank or Cash.
- Original source and account raw fields retain SOH. The raw-field exception is
  limited to accounts and malformed `Account` records retained as evidence.
  Malformed/ambiguous accounts still block transactional CSV exports.
- Normalized fields and destination/review CSV keep strict text validation.
  Native QIF intentionally retains original source, including the marker.
- Canonical schema remains 1.0.0. Alpha1/alpha2 archives upgrade generator
  metadata only. Full source reparse and exact canonical comparison still detect
  altered warnings, raw evidence, normalized data and source interpretations.

## Fictional regression example

This example is independently invented. Generate the actual SOH programmatically;
the six printable characters `\u0001` are not the original control byte.

```js
const qif = [
  "!Option:AutoSwitch", "!Account",
  "NFictional Unspecified Account", "T\u0001", "^",
  "!Clear:AutoSwitch", "!Account",
  "NFictional Checking", "TBank", "^", "!Type:Bank   ",
  "D11/24/2026", "T-42.75", "PFictional Store", "^", "",
].join("\r\n");
```

The catalogue account remains present with type `""`; the transaction belongs
to the explicit Bank account. Tests also cover deriving a type from an explicit
selected section, balanced splits, unknown sections, malformed/ambiguous account
context, controls in other fields, later rejected controls, and terminal Ctrl-Z.
